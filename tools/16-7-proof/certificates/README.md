# Certificates for discarded patterns: pilot

The proof in `../two-shapes.ipynb` uses one number from the literature: at most 228 distance patterns
occur for ten points in the plane with at most six distances (Szöllősi and Östergård, Table 9). That
number comes out of a generation, level by level from four to ten points, in which candidates are
*discarded* when a system of polynomial equations has no admissible solution. This folder is the start of
a derivation of the 228 in which every discard comes with a certificate that can be checked by
multiplying polynomials, and nothing else.

Status (17 November 2026): the five-point level is complete, and a random sample of the six-point level
has been done as a pilot. Levels six and seven in full are still to do.

## What a certificate is

Take a pattern on n points with colours 0..k-1, and suppose points of the plane have it, with squared
distances x_0, ..., x_{k-1} (positive and pairwise different). For a base point b put

    G_ij = x_c(b,i) + x_c(b,j) - x_c(i,j),        G_ii = 2 x_c(b,i)        (i, j different from b)

where c(i,j) is the colour of the pair. This is twice the Gram matrix of the vectors p_i - p_b, which lie
in a plane, so every 3x3 minor of G is zero. The minors are cubic polynomials in the x.

A certificate is a polynomial identity

    scale * (a product of factors x_c and x_a - x_b)  =  sum of (polynomial) * (minor)

with a non-zero integer `scale`. At the point x the right side is zero and the left side is not, so no
such points exist. Example, the first five-point certificate (four points at one distance from point 0,
the other pairs coloured as in the file):

    18 x_0^3  =  13 M_0(123;123) - 3 M_1(234;234) - 22 M_0(123;124)

where M_b(rows;columns) is the minor of G for the base point b.

`check.py` checks such identities. It is about seventy lines of pure Python, uses integers only, and
recomputes the minors from the pattern itself. It is the only code here that has to be trusted.

    python3 check.py level5.jsonl pilot6.jsonl.gz

How a certificate was found does not matter for its validity. For the record: `find.py` works modulo a
prime with the degree-d parts of the ideal generated by the minors, looks for a product of d forbidden
factors in it (d = 3, 4, ...), and then solves for the multipliers exactly.

## Results

| | five points (all candidates) | six points (random sample) |
|---|---:|---:|
| candidates | 1,193 | 1,060 of 537,230 |
| with a certificate | 271 | 1,010 |
| kept | 922 | 50 |
| degree of the product: 3 / 4 / 5 | 237 / 34 / 0 | 761 / 248 / 1 |
| bytes per certificate, median / largest | 297 / 676 | 1,836 / 12,262 |
| search, per candidate | | 85 ms |
| check, per certificate (pure Python) | | 3.9 ms |

All 1,282 certificates (including one for the one-coloured four-point pattern) pass `check.py`.

Agreement with the known numbers:

* Five points: 271 discarded and 922 kept, with the same breakdown by number of colours as the earlier
  run modulo primes (kept: 1, 20, 248, 409, 244 for two to six colours), and the same 922 as in the table
  of Szöllősi and Östergård.
* Extending the 922 kept patterns by one point gives 537,230 six-point candidates, their number again
  (generated with `tools/fixed-distances/g7fin/gen/gen.py --gen-only`).
* Six points: 50 of the 1,060 sampled candidates are kept (4.7 %); the full level keeps
  20,229 of 537,230 (3.8 %). The difference is within sampling error, and `kept_check.py` confirms that
  nothing was missed: for each of the 50 there is, modulo the prime, a solution of the equations at
  which no forbidden factor vanishes, so no certificate can exist. A search with products of degree up
  to 8 finds none for them either.

## What the full run would take (extrapolated from the pilot)

* Six points: 537,230 candidates at 85 ms is about 13 core-hours. About 517,000 certificates, about
  1.1 GB as JSON lines and 0.2 GB compressed, so they cannot live in this repository as they are;
  checking all of them takes about 35 minutes of pure Python.
* Seven points: 14,732 candidates, of which 10,065 should get a certificate.
* From eight points on nothing is discarded, so levels eight to ten are generation only.
* The certificates are larger than they need to be: the multipliers come from the first solution found,
  with a median of 41 multiples of minors and occasionally very large integers.

## Files

| file | what it is |
|---|---|
| `check.py` | the checker |
| `level5.jsonl` | 272 certificates: the one-coloured four-point pattern and all 271 discarded five-point candidates |
| `L5.json` | the 922 five-point patterns that are kept |
| `pilot6_sample.json` | the 1,060 sampled six-point candidates (seed 20261117; index in the sorted list of candidates) |
| `pilot6.jsonl.gz` | the 1,010 certificates of the sample |
| `pilot6_kept.json` | the 50 sampled candidates without a certificate |
| `find.py` | the search (numpy, python-flint) |
| `run_level5.py`, `run_pilot6.py` | regenerate the files above; both reproduce them byte for byte |
| `kept_check.py` | the check on the kept side described above (not part of any proof) |

A certificate is one JSON object per line: `n`, `pattern`, `scale`, `product` (factors `[c]` for x_c or
`[a, b]` for x_a - x_b, each with its exponent) and `terms` (base point, rows, columns, and the multiplier
as a list of `[coefficient, exponents]`).
