# gen: hereditary generation of candidate patterns of n-point planar sets with <= 6 distances

Reproduces the orderly generation of Szöllősi–Östergård (arXiv:1804.06040, Table 9, d = 2, s = 6)
level by level, with checkpoints, and (optionally) finishes with a real-realizability check.

## Files

| file | purpose |
|---|---|
| `patlib.py` | patterns as rgf-normalised colour tuples over `itertools.combinations(range(n),2)`; canonical form / certificate via nauty (`pynauty`, built from source into `/usr/local/lib/python3.13/dist-packages/pynauty`; sources in `ext/`) on the incidence encoding (points, edge-vertices, colour-vertices as three cells, so vertex AND colour permutations are automorphisms) |
| `realize.py` | polynomial systems (fully expanded, integer coefficients, msolve syntax) and msolve drivers. `system_gram` = S–Ö's own system (all 3×3 minors of C_ij = s_0i + s_0j − s_ij, C_ii = 2 s_0i, plus the Rabinowitsch equation); `system_coords` = the coordinate system of `certify5d.py` / `pat_rigid.py` (p0 = (0,0), p1 = (x1,0), colour of (0,1) = 1). `msolve_gb_trivial` = "is the reduced Gröbner basis mod p equal to {1}" |
| `gen.py` | the generator (see below) |
| `realcheck.py` | real realizability of a level's list over Q (msolve `-p 200`, random hyperplane sections for positive-dimensional cases) |
| `validate.py` | compares a `levels/` directory with Table 9 and with the certified lists `scratchpad/cert4*.json`, `cert5*.json`, and with `g7fin/patterns_10.json` |
| `export.py` | writes a level in the `g7fin/patterns_{n}.json` format |

## Definitions and criteria

* pattern on n points = edge colouring of K_n with <= 6 colours up to vertex and colour permutations.
* **raw_n** (Table 9 row 1, "candidate Gram matrices"): patterns on n points every one of whose
  (n−1)-point induced sub-patterns is in **L_{n−1}**. At n = 4, raw_4 = all 25 colourings of K_4.
* **L_n** (Table 9 row 2, "satisfying (5)"): the raw_n patterns that are *complex-realizable with
  distinct nonzero values*: the ideal generated by the rank <= 2 conditions (or equivalently the
  coordinate equations) together with t·∏_{a<b}(s_a − s_b)·∏_{c>=1} s_c − 1 is proper (Gröbner basis ≠ {1}).
  This is exactly S–Ö's Proposition 4.2 with d = 2 (their auxiliary variable u = our t).
* The monochromatic K_4 is the only pattern removed at n = 4 (25 → 24), and raw_5 = 1193 = 1205 − 12 is
  the number of K_5 colourings with no monochromatic K_4. So "candidates" are hereditary with respect to
  the *pruned* list of the previous level, and the pruning is the complex test — this reproduces
  25/24, 1193/922 and 537230 exactly (see Validation).

The complex test is done mod the prime 1073741827 (msolve `-g 2` with the characteristic in the input
file). A pattern is discarded only when the basis is {1}; by default every discard is confirmed mod a
second prime 1073741789 (`--no-confirm` switches that off; a disagreement is kept and flagged with
status 2 in `test{n}.json`, msolve errors/timeouts are kept and flagged with status 3). Keeping a false
positive is harmless (the final real check removes it); the confirmation guards against the (tiny)
chance of an unlucky prime discarding a realizable pattern.

Method: `--method auto` (default) uses the Gram-minor system for n <= 7 (fastest there) and the
coordinate system for n >= 8 (fewer polynomials). The two formulations were cross-checked on 60 K_5
types and 209 level-6 candidates (all agree), and the fast Gram-system generator was checked to produce
exactly the same polynomials as the reference implementation on all 1193 K_5 candidates, 3000 random
level-6 candidates and 100 level-7 patterns.

## Algorithm (gen.py)

For each parent P in L_{n−1} (vertices 0..n−2), add vertex v = n−1 and choose the colours of the edges
(0,v), (1,v), … by depth-first search; new colours are introduced in increasing order and at most 6
colours are used in total. After colouring (i,v), every induced sub-pattern that contains both i and v
and has order j <= min(i+2, n−1) is checked: orders 4 and 5 by table lookup (`lookup_table`: all rgf
labelled colourings of K_4 / K_5 whose canonical form is in L_4 / L_5; 203 and 109299 entries), orders
>= 6 by nauty canonical form in the set L_j. (K_4 checks are skipped where a K_5 check at the same step
contains them.) Each completed extension is canonicalised with nauty and inserted in a set → raw_n.
Then every raw_n pattern is tested (test phase, checkpointed every 500) → L_n.

Output directory (`--out`, default `gen/levels/`): `raw{n}.json`, `test{n}.json` (checkpoint),
`L{n}.json`, `summary.json`, `gen.log`. Rerunning the same command resumes: finished levels are loaded,
a half-tested level continues from the checkpoint. Temp files for msolve are `gen/tmp/ms_{in,out}_<pid>.txt`
(the pid is taken at call time, so forked workers never share a file).

```
cd /tmp/claude-0/-home-claude/27d8f328-c517-545a-96bf-782e414fcf24/scratchpad/g7fin/gen
nohup python3 gen.py --to 10 --out levels --workers 1 > levels_run.log 2>&1 &

# progress: tail -f levels/gen.log ; resume after an interruption with the same command.
python3 validate.py --levels levels          # counts vs Table 9, cert lists, known 10-point patterns
python3 realcheck.py 10 --levels levels      # real realizability of L_10 (-> levels/real10.json)
python3 export.py 10 --levels levels         # -> levels/patterns_10_L.json in the patterns_10.json format
```
Add `--no-confirm` to halve the level-6 test time. `--workers 2` only helps on a machine with two real
cores. Note: S–Ö's row 2 is blank for n >= 9, i.e. their 635 / 228 / 62 are row-1 (raw) counts; this
pipeline applies the complex test at every level, so compare both `raw{n}` and `L{n}` with their numbers.

## msolve pitfalls (all silent)

* polynomials must be fully expanded with integer coefficients; no parentheses, no rationals;
* a term with coefficient 0 (`0*x`) makes msolve return "infinitely many solutions" — never emit it;
* a coefficient divisible by the chosen prime is a hard error ("coefficient cannot be 0 modulo p");
* the characteristic goes on line 2 of the input file; with `-g 2` and characteristic 0 the basis
  printed is for msolve's own first prime.
